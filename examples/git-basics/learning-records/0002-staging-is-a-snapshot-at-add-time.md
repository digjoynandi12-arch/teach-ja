# 誤解の修正: git add のあとの編集は、自動ではコミットに入らない

「`git add` したあとに編集した分も、コミットのときに自動で入る」と思っていたが、レッスン0001で「`git add` した時点の内容がステージされ、あとから編集した分はもう一度 `git add` しないと入らない」と理解し直した（2026-11-15）。ステージングエリアを本人の言葉で「次のコミットの下書き」と表現している。

## 根拠

- レッスン0001のクイズは4問中3問正解。間違えたのは、この誤解を問う2問目だけ。
- 間違えた理由と正しい理解を、自分の言葉で説明できた。
- ターミナルの手順（ステージ後に再編集してコミット、`git diff` と `git diff --staged` の見比べ）を自分の環境ですべて実行した。

## 今後への影響

- 「3つの場所」と `git status` の読み方は前提にしてよい。次は履歴を読む（`git log`）とコミットの単位に進める。
- 元の誤解は「Gitはファイル単位で追いかけて、最新を拾ってくれる」という見方から来ている可能性がある（これは教える側の推測）。同じ見方は `git commit -a`、プッシュし忘れ、プルリクエストに後からコミットが加わる場面でまた顔を出しそうなので、そこで「記録されるのは、その時点のスナップショット」と結び直す。
- 次回の冒頭で、この点を間隔をあけて思い出す問題を1〜2問入れる。
