# ミッション: GitとGitHubでのチーム開発

## なぜ学ぶのか
2026年12月から社内のチーム開発に参加する。GitHub上で自分のブランチを切り、プルリクエストを出し、レビューを受けて直すところまでを、手順の丸暗記ではなく意味をわかったうえで一人で進められるようになりたい。

## 達成できたと言える状態
- 作業用のブランチを切り、意図した変更だけをコミットして、GitHubにプッシュできる
- プルリクエストを作成し、レビューの指摘を追加のコミットで反映できる
- `git status` の表示を読んで、変更が今どこにあるか（作業ディレクトリ・ステージングエリア・リポジトリ）を説明できる
- コンフリクトが起きても、何が起きているかを説明でき、落ち着いて解消できる

## 出発点
- `git add` と `git commit` は打ったことがあるが、意味はよくわかっていない
- ステージングとコミットの違いがあいまい
- コンフリクトが怖い
- ターミナルは少しだけ使える

## 制約
- 1回のレッスンは20分くらい
- 期限は1ヶ月（2026年12月中旬のチーム参加まで）
- 文体はです・ます調
- 社内に #git-help というSlackチャンネルがある

## 対象外
- リベース（rebase）、チェリーピック（cherry-pick）などの履歴の書き換え
- Gitの内部構造（オブジェクト、ハッシュの仕組み）
- GitHub ActionsなどのCI/CD
- GUIクライアントの使い方（チームが指定している場合は見直す）
